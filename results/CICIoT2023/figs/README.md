(Fig-5 analogue) on the CICIoT2023 pilot. Generated by
[`../plot_cic_rmse.py`](../plot_cic_rmse.py) from cached per-test-packet score arrays — **no
pipeline re-run**; all arrays were produced earlier by `run_ciciot2023.py` (double-tanh /
committed pipeline).

## What each axis is (and where the array comes from)

Both detectors are plotted on the **held-out test stream** = `[benign_test 30k negatives]` +
`[attack 50k positives]` = **80,000 packets** (see `../stream_counts.csv`). Index 0 is the
first benign_test packet; the **attack begins at packet 30,000** (`n_test`). Every array is
aligned 1:1 with `arr_gold_<attack>.npy` (0 = benign, 1 = attack).

- **x-axis** — packet index in the held-out test stream (0 … 80,000).
- **y-axis (Kitsune, Fig 4)** — per-packet reconstruction anomaly score `tanh(RMSE)`, the
  KitNET/X1 output. **Array:** `../arr_kitsune_<attack>.npy` (identical to
  `../kitsune_testscores_<attack>.npy`; this is `tanh(raw RMSE)` on the test region, i.e. the
  driver's Kitsune baseline score, `run_ciciot2023.py:172,176,199`). **log scale.**
- **y-axis (Tenko, Fig 5)** — node-aggregated anomaly score `S(n)` (Tenko's X2 node score),
  the per-packet node score. **Array:** `../arr_node_<attack>_double.npy` (identical to
  `../tenko_nodescore_<attack>.npy`, `run_ciciot2023.py:197,214`). This is the direct
  anomaly-score analogue of Kitsune's per-packet RMSE (both are per-packet scores in `[0,1]`),
  which is why the two panels line up on the same log-y range. Its threshold-independent AUC
  (`tenko_AUC_nodescore`) matches the headline fused pattern-distance AUC to ~1e-3 (e.g.
  DoS-SYN 0.987889 vs 0.987792; see `../ciciot2023_tenko_signal_breakdown.csv`), so it is a
  faithful "score used for AUC". **log scale.**

> Note on the Tenko "score". Tenko's *headline* threshold-independent AUC/EER in the report is
> computed on the **fused η-normalized pattern distance** (`arr_cont_<attack>_double.npy` /
> `tenko_patterndist_*`), not on `S(n)`. We plot `S(n)` here because it is the per-packet
> **anomaly score in `[0,1]`** and therefore the correct visual analogue of Kitsune's RMSE
> timeline (same y-axis semantics). The pattern distance is an unbounded benign-normalized
> distance (benign≈0.3, attack≈20–24) and does not share Kitsune's `[0,1]` axis. Because
> `AUC_nodescore ≈ AUC_patterndist`, the picture is the same either way.

## Threshold line (benign-calibrated cutoff)

Horizontal dashed line = **benign-calibrated Median+MAD** cutoff,
`thr = median + 3 · 1.4826 · MAD`, computed on the **benign_test negatives** (the plotted
benign region, indices `0 … 29,999`) of each detector's own stream. This is the report's
Kitsune Median+MAD recipe (`run_ciciot2023.py:115–118`, `MAD_K = 3.0`) applied to each
detector's plotted benign region so both panels use one identical recipe.

| Detector | Threshold (benign_test-calibrated, plotted) |
|---|---|
| Kitsune `tanh(RMSE)` | **0.01281** |
| Tenko `S(n)` | **0.01578** |

Cross-check: the `run_ciciot2023.py` driver calibrates Kitsune's *operating* threshold on the
earlier **benign_lead** slice `[55001:150000]`, giving `thr = 0.00984` — numerically close to
the plotted 0.01281 (same recipe, different benign slice). We use the benign_test-calibrated
value for both panels because (a) it is reproducible from the exact arrays plotted, and (b) it
gives one identical recipe across the two detectors.

## Downsampling

**Factor = 10** (stride subsample: every 10th test packet → 8,000 of 80,000 points shown).
The attack-onset transition at index 30,000 and the threshold-crossing structure are preserved
because the flood/spoofing signal is sustained. The factor is annotated on each figure.

## Per-device ROC (the clear Tenko win on MITM)

`cic_roc_mitm_clearwin.png` / `.pdf` — generated by
[`../plot_cic_roc.py`](../plot_cic_roc.py). This is the single cleanest demonstration that
Tenko beats Kitsune on MITM: at the **packet level** the detectors are near-tied
(AUC 0.949 vs 0.942, shown as the faded thin curves), but at the **source/device level** — the
operationally meaningful "which device is malicious?" question — Tenko wins decisively:

| Detector | Per-device ROC-AUC (MITM) |
|---|---|
| **Tenko** (orange) | **0.839** |
| **Kitsune** (blue) | **0.647** |

Both AUCs are recomputed from the cached arrays and asserted to match
`../ciciot2023_source_level_metrics.csv` to <1e-2 (they match to 1e-6: 0.839252 / 0.646729).

**Faithfulness (verified).** This scoring is the one audited in
[`../source_level_faithfulness.md`](../source_level_faithfulness.md) and reproduced by
[`../_faithful_recompute.py`](../_faithful_recompute.py): the Tenko device score is the **max
over a device's packets of the fused node-tolerance statistic** `nd = ‖z−μ‖ / (max benign
deviation)` (= `arr_cont = 0.5·nd_g + 0.5·nd_s`, `results.py:946-956`), which is exactly the
threshold-independent statistic Tenko's tolerance layer thresholds at η and that
`run_ciciot2023.py` reports as Tenko's official AUC. `max` is not a generic reduction — it is
the threshold-free form of Tenko's native "flag a node the first time its pattern leaves the
benign envelope" rule (there is no patience/consecutive-N counter). The same "ever-fired = max
of decision statistic" rule is applied to Kitsune's per-packet `tanh(RMSE)` (Kitsune has no
node state), so the reduction is symmetric and disclosed. Scoring by the raw node score `S(n)`
(`arr_node`) instead does **not** win — the win is specifically a tolerance-layer effect.

**Per-device scoring (reproduced exactly from `../source_level_experiment.py` /
`../_faithful_recompute.py`):**

- **Detector signals (per-device = MAX over that source's test packets):**
  Kitsune = max of per-packet `tanh(RMSE)` (`../arr_kitsune_MITM-ArpSpoofing.npy`);
  Tenko = max of per-packet **fused tolerance statistic** `nd`
  (`../arr_cont_MITM-ArpSpoofing_double.npy`), the threshold-independent signal behind the
  headline AUC — **not** the raw node score `S(n)` (`arr_node`).
- **Per-packet source IPs:** read live from `<path-to-ciciot2023-pilot>/stream_MITM-ArpSpoofing.pcap.tsv`
  (col 4 IPv4, else col 17 IPv6), test region = `src_all[150000:]`, aligned 1:1 with the 80k
  cached score arrays.
- **Attacker-device set (score-independent, not circular):** internal `192.168.x` sources with
  `>=50` packets in the attack region **and** `>=99%` of the source's packets falling in the
  attack region. Sources with `<5` test packets are dropped. For MITM this yields
  **10 attacker devices vs 214 benign devices**.
- **Curves:** `sklearn.metrics.roc_curve` per detector; AUC via `roc_auc_score` (same as the
  source-level script). Bold = device-level; thin/faded = packet-level contrast.

Reproduce:

```bash
.venv/bin/python results/CICIoT2023/plot_cic_roc.py
```

## Full-stream overlays with the training period marked (Fig 4/5-style)

`cic_fullstream_overlay_DoS-SYN_Flood.{png,pdf}` and
`cic_fullstream_overlay_MITM-ArpSpoofing.{png,pdf}` — generated by the `fullstream` mode of
[`../plot_cic_rmse.py`](../plot_cic_rmse.py). Unlike the test-only overlays above (which show
only the 80k test region), these span the **full 230,000-packet per-attack stream** and mark the
**training period**, following the standard Kitsune-style RMSE-timeline layout (shaded training
region on the left, then benign-test and execution/attack regions).

> **Fig 4/5 styling note (assumption).** The manuscript's exact Fig 4/5 source is not on disk
> (`cic_experiment_report.tex` is figure-free and `cic_final_comparison.tex` references the other
> figures here), so these mirror the standard Kitsune RMSE-timeline convention — log-y anomaly
> score, shaded training region, execution/attack region — matching the styling of the other
> figures in this folder (colors, median-pooled lines, benign-calibrated thresholds).

**Region boundaries marked** (from `../stream_counts.csv` and `run_ciciot2023.py:34-37`):

| Region | Index range | Marking |
|---|---|---|
| Training (benign only): KitNET train + η/threshold calibration | `[0 : 150000]` | blue shaded band + label |
| — calibration start (FMgrace+ADgrace+1) | `55001` | dotted vertical line |
| — train/test split | `150000` | dash-dot vertical line |
| benign_test (negatives) | `[150000 : 180000]` | grey shaded band + label |
| **attack onset** | `180000` | dotted vertical line |
| attack (positives) | `[180000 : 230000]` | red shaded band + "Attack" label |

**Data coverage / which detector spans what (honest disclosure):**

- **Kitsune — full stream.** Curve = `tanh(rmse_raw_<attack>.npy)` over `[0:230000]`; the cached
  full-stream RMSE. (Verified: `tanh(rmse_raw)[150000:]` is identical to `arr_kitsune_*`.)
- **Tenko — test region only `[150000:230000]`, NOT recomputed.** The driver persists Tenko's
  per-packet arrays for the test region only (`run_ciciot2023.py` collects `node_scores_test`
  etc. from `benignLimit` onward), so the cached node score `S(n)` (`arr_node_<attack>_double.npy`)
  begins at packet 150,000. **I used cached arrays (option b): the Tenko curve therefore starts at
  the train/test split, and the training region is shaded/labelled to show the full protocol.** No
  pipeline re-run was performed. (This is also principled: Tenko's tolerance statistic is only
  defined after the benign envelope is built during training.)
- **Thresholds:** benign-calibrated Median+3·1.4826·MAD on the benign_test slice — Kitsune 0.0128,
  Tenko 0.0158 (same recipe/values as the other figures).
- **Downsampling / smoothing:** faint points = every **20th** packet (230k stream);
  bold lines = **250-packet block-median** pool. Both annotated on the figure.

## Mixed combined-stream RMSE timeline (Kitsune vs Tenko, single-tanh)

**Files:** `mixed_rmse_tenko_kitsune.png` / `.pdf` (primary two-panel figure);
`mixed_rmse_kitsune.png/.pdf` and `mixed_rmse_tenko.png/.pdf` (single-panel variants).

**Script:** `../mixed/plot_mixed_rmse.py` (loads cached arrays only — **no KitNET/Tenko re-run**).
Run with:

```bash
MPLCONFIGDIR=/tmp/mplcache MPLBACKEND=Agg \
  .venv/bin/python results/CICIoT2023/mixed/plot_mixed_rmse.py
```

**Configuration:** single-tanh Tenko on the reduced/rationalized benign split, committed
operating point $\eta_\text{global}=50$, $\eta_\text{node}=20$, `benignLimit=60000`. "Single-tanh"
= the RAW KitNET RMSE was fed to Tenko so Tenko's internal tanh is the only normalization; the
Kitsune baseline score is $\tanh(\text{raw RMSE})$.

**Full-stream region boundaries** (stream packet index, `x = 0..420000`):

| Region | Stream index | Meaning |
|---|---|---|
| KitNET feature-map grace | `[0:5000]` | FM grace |
| KitNET anomaly-detector grace | `[5000:55000]` | AD grace (⇒ 55k total KitNET training) |
| Tenko pattern-model calibration | `[55000:60000]` | 5k calib; **benign training limit @ 60000** |
| benign test | `[60000:120000]` | benign held-out; **attack onset @ 120000** |
| DoS-SYN_Flood | `[120000:170000]` | attack block 1 |
| DDoS-UDP_Flood | `[170000:220000]` | attack block 2 |
| Recon-OSScan | `[220000:270000]` | attack block 3 |
| MITM-ArpSpoofing | `[270000:320000]` | attack block 4 |
| Mirai-greeth_flood | `[320000:370000]` | attack block 5 |
| DictionaryBruteForce | `[370000:420000]` | attack block 6 |

Boundaries read from and verified against `../mixed/attack_blocks.csv`.

**Thresholds shown:**
- Kitsune Median+MAD threshold (top panel, red dashed): `thr = 0.009577977360449396`
  (`med = 0.004223319748494231`, `mad = 0.0012038890264749235`, recipe `med + 3·1.4826·mad`),
  calibrated on the benign calibration slice `[55001:60000]` (from `../mixed/mixed_summary.json`).
- Tenko committed decision (bottom panel): flag iff $nd_g > 50$ **OR** $nd_s > 20$; both
  $\eta$ lines drawn dashed in their channel colors.

**Panels:** TOP = Kitsune $\tanh(\text{rmse\_raw})$ over the **full** stream `[0:420000]`
(so the training region is visible), colored benign (blue, `stream<120000`) vs attack (red).
BOTTOM = Tenko decision channels $nd_g$ (green) and $nd_s$ (node, purple) over the test region,
starting at `x=60000` (no Tenko score before calibration ends). A single-panel Tenko variant
(`mixed_rmse_tenko.*`) instead plots the fused continuous score `arr_cont` with points colored
by the OR-rule flag.

**Operating stats reproduced from the arrays (benign test `[60k:120k]`):** Kitsune benign-test
FPR (fraction of benign packets above its threshold) = **0.2136**; Tenko benign flag rate =
**0.0069**; Tenko attack flag rate (TPR) = **0.8793**. This is the headline contrast:
benign spikes routinely cross Kitsune's low Median+MAD threshold, whereas Tenko's node/global
normalization keeps benign deviations far below $\eta$ and only fires on sustained attack structure.

### Confusion-outcome variant (TP/TN/FP/FN at the committed operating point)

**Files:** `mixed_rmse_confusion.png` / `.pdf` (primary two-panel);
`mixed_rmse_kitsune_confusion.*` and `mixed_rmse_tenko_confusion.*` (single-panel variants).
Same script `../mixed/plot_mixed_rmse.py` (functions `two_panel_confusion`,
`kitsune_single_confusion`, `tenko_single_confusion`), same cached arrays, no re-run.

Each point is colored by its confusion class at the **committed operating point**:
TN benign→benign green `#009E73`, TP attack→attack red `#D55E00`, **FP** benign→attack orange
`#E69F00` (highlighted: larger/darker, drawn on top), **FN** attack→benign blue `#0072B2`
(highlighted). Downsampling drops only the dense TP/TN masses (every 15th); **all FP and FN points
are plotted** so no error is hidden. The legend lists all four classes with their counts.

- **Kitsune** (top, full stream): `pred = tanh(rmse_raw) > 0.009577977360449396`; full-stream label
  `[0:120000]=benign`, `[120000:420000]=attack`. Median+MAD threshold line retained.
- **Tenko** (bottom, test region from `x=60000`): committed prediction `../mixed/arr_pred_mixed.npy`
  (verified in-script to equal `(nd_g>50)|(nd_s>20)`, 0 mismatch) vs `../mixed/arr_gold_mixed.npy`;
  y-score is the fused `../mixed/arr_cont_mixed.npy`; $\eta$ lines shown as grey references.

**Confusion counts (reproduced from the arrays):**

| Detector | TP | TN | FP | FN |
|---|---|---|---|---|
| Kitsune (full stream) | 289,342 | 82,901 | 37,099 | 10,658 |
| Tenko (test region) | 263,791 | 59,583 | 417 | 36,209 |

Tenko matches the known combined-run confusion (263791 / 59583 / 417 / 36209) **exactly**.
Kitsune's FP (orange) concentrate across the benign region `[0:120000]` (benign spikes above its
low threshold); Tenko's FN (blue) concentrate in the low-rate **Recon-OSScan** (18,888 FN) and
**DictionaryBruteForce** (9,994 FN) blocks, with Tenko FP a thin orange sliver (417) in the benign
test window.
