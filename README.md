
# README for Network Intrusion Detection with the improved kitsune

## Overview

This repository contains a network intrusion detection workflow that was originally developed to analyze network traffic and detect adversarial IPs using PCAP files. The codebase consists of two primary scripts:

 1. example.py: Handles the evaluation process by running the detection system on a given PCAP file and generating intermediate results such as RMSE values.
    
   
 2. results.py: Uses the results generated by example.py (e.g., RMSE values) to perform further analysis and generate confusion matrices for evaluation.

## Original Workflow

Initially, the workflow required running the scripts in a hardcoded sequence:

example.py was executed with hardcoded input files to process a PCAP file and generate outputs like RMSEs.pkl.

results.py then consumed these outputs, along with additional hardcoded files such as TSVs (parsed from the original PCAP) and labels, to perform further analysis.

This process required manually changing the file paths in the scripts, making it rigid and less adaptable for different datasets or scenarios.

## Streamlined Workflow

To streamline the workflow, a new script (e.g., Workflow.py) has been introduced:

### Features

**Parameterization**: Accepts input parameters for the PCAP file, TSV file, label file, and saved RMSE files via command-line arguments.

**Dynamic Processing**: Determines whether to use a saved RMSE file or process the PCAP file from scratch.

**Blockchain Mode**: Allows selecting different modes (offline, blocking, or parallel) via command-line flags.

### Known Limitations

**Untested**: This new script has not been thoroughly tested. If any issues arise, please revert to using the original workflow with example.py and results.py.

## Suggested Workflow

 1. Using the New Script:
    
        python unified_script.py -i <input_pcap> -ip <tsv_file> -l <label_file> -o
    
    or, if you have a saved RMSE file:
    
        python unified_script.py -r <saved_RMSE> -ip <tsv_file> -l <label_file> -b
 2. Reverting to the Original Workflow:
    
	- Modify the file paths directly in example.py and results.py as  needed.
    - Run the scripts in sequence:
    
	        python example.py
	        python results.py

## Notes for Users

- The original hardcoded workflow is fully functional but hard to comprehend. Use it as a fallback if the new script fails.

- Ensure that required files (e.g., PCAP, TSV, and label files) are properly organized and paths are correctly specified.

- Test the new script on a small dataset to validate its functionality before scaling.

- Contributions or fixes to the new script are welcome and encouraged to make the workflow more robust.
